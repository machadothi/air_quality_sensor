# Architecture

How the firmware is put together: the modules, the libraries they use, how
they talk to each other, and why the code is shaped by the ESP8266's RAM.

## Overview

```
                    ┌──────────────────────── ESP8266 (MicroPython) ────────────────────────┐
                    │                                                                         │
  ENS160 ──┐        │   sensors.py ──readings──► app.py main loop ──state JSON──► net.py ─────┼── Wi-Fi ── MQTT broker ── Home Assistant
  AHT21  ──┼─ I2C ──┤   (AirSensor)              (App.loop)        ◄──requests── (Net)     │                        └─ phone app
  SSD1306 ─┘        │                               │    ▲                         │          │
                    │                               ▼    └──── commands.py ◄───────┘          │
                    │                     ui.py + gfx.py ◄── assets.bin (flash)               │
                    └─────────────────────────────────────────────────────────────────────────┘
```

Everything runs in **one thread, one loop**. Each job runs when it is due and
returns within milliseconds; nothing calls `sleep(60)`. That is what keeps the
display animating and requests answered while Wi-Fi is down or a sensor is
missing.

## Modules (`firmware/`)

| Module | Responsibility | Talks to |
|---|---|---|
| `boot.py` | runs first at every boot; only `gc.collect()` (keep it minimal: an error here can lock you out of the REPL) | |
| `main.py` | runs after `boot.py`; calls `app.run()` | `app` |
| `app.py` | loads `config.json` and fills in `DEFAULTS`; creates the I2C bus, display, sensors and network; the main loop; the watchdog; builds the published JSON; restarts the board on a crash | everything |
| `sensors.py` | `AirSensor`: drives the ENS160 and AHT21 without blocking, feeds compensation, verifies reads (checksum), reads raw resistances and firmware, sums readings for averaging, re-detects sensors; dew point, absolute humidity, TVOC in µg/m³ | I2C |
| `net.py` | Wi-Fi station, MQTT client with reconnect/backoff, keepalive, last will, publishing; disables the ESP8266's default access point | `network`, `umqtt.simple` |
| `commands.py` | answers MQTT requests (`/status`, `/read_all`, `/display`, …); **loaded per request**, then dropped; saves display choices to `settings.json` | `app`, `net`, `ui` |
| `home_assistant.py` | Home Assistant MQTT discovery messages; **loaded only when enabled**, after each MQTT connect | `net` |
| `ble.py` | ESP32 only: Bluetooth LE GATT service (the BLE Sensor protocol) and BTHome broadcasts, see [bluetooth.md](bluetooth.md) | `bluetooth`, `app` |
| `ui.py` | the pages, header/footer, slide transition, the chart history | `ssd1306`, `gfx` |
| `ui_more.py` | ESP32 only: the extra display pages (dew point, sensor details, system) | `ui`, `sensors` |
| `gfx.py` | proportional text, icons, sparklines on top of `framebuf`; reads glyphs from `assets.bin` | `framebuf`, `assets` |
| `assets.py` + `assets.bin` | font metrics and glyph positions (RAM) + the bitmaps (flash); generated by `tools/make_assets.py` | |

## Libraries

Everything comes with the MicroPython firmware; nothing has to be installed
on the board.

| Library | Kind | Used for |
|---|---|---|
| `machine` | built in | `Pin`, `SoftI2C` (bit-banged I2C on the ESP8266) / `I2C` (hardware, ESP32), `Timer` (watchdog), `reset`, `freq`, `unique_id` |
| `bluetooth` | built in (ESP32) | BLE: advertising, GATT server, notifications |
| `network` | built in | `WLAN` station (Wi-Fi client) and access point (switched off) |
| `framebuf` | built in | 1-bit frame buffers: pixels, lines, rectangles, `blit` with transparency and palette, `scroll` |
| `ssd1306` | frozen (micropython-lib) | the OLED controller: init, `show()`, `contrast()`, `rotate()` |
| `umqtt.simple` | frozen (micropython-lib) | MQTT 3.1.1 client: connect, subscribe, publish, `check_msg`, `ping`, last will |
| `json`, `array`, `gc`, `time`, `sys`, `math` | built in | config, messages, compact history, memory, timing |

"Frozen" means compiled into the firmware image, so it costs no RAM for its
code. `help('modules')` in the REPL lists them all.

On the PC: **mpremote** (file transfer and REPL over USB serial),
**mpy-cross** (compiler), **esptool** (flashing), **Pillow** (fonts, icons,
previews).

## The main loop (`App.loop` in `app.py`)

```
forever, every ~20 ms:
    watchdog.feed()
    air.update()              # ENS160 every 1 s, AHT21 every 2 s, non-blocking
    net.poll()                # Wi-Fi state, MQTT (re)connect, incoming requests, keepalive ping
    every publish_s (60 s):   publish averaged readings
    every 60 s:               add a point to each chart
    every page_s (5 s):       slide to the next page        (~0.6 s)
    else every 1 s:           redraw the current page       (~90 ms)
    every 10 s:               record the lowest free RAM
```

Timers use `time.ticks_ms()` with `ticks_diff`/`ticks_add`, which handle the
counter wrapping around.

### Start-up

`App.__init__` creates the display **first**: its two 1 KB frame buffers need
contiguous RAM, which is easiest to get before anything else fragments it.
Then the sensors and the network. `App.connect()` shows the start screen while
Wi-Fi connects (at most 8 s) and moves on regardless.

### Failure handling

| What goes wrong | What happens |
|---|---|
| Wi-Fi drops | the ESP8266 reconnects by itself; after 30 s without success `net.py` calls `connect()` again. The display keeps running. |
| MQTT broker unreachable or refuses | retry after 5 s, doubling up to 2 min |
| MQTT connection dies | detected on the next publish/ping/check; dropped and reconnected |
| A sensor stops answering | its values become `null`/"No sensor"; looked for again every 30 s |
| The loop hangs (e.g. a stuck socket) | the software watchdog (a `Timer` checking every 5 s) resets the board after 120 s |
| An exception escapes | printed, shown on the display ("Error"), board restarts after 10 s |
| Ctrl+C (mpremote) | the program stops cleanly, the watchdog timer is stopped, you get the REPL |

## One code base, two boards

`app.py` reads `sys.platform` (`esp32` or `esp8266`) and adapts:

| | ESP8266 | ESP32 |
|---|---|---|
| I2C | `SoftI2C` on GPIO5/4 | hardware `I2C(0)` on GPIO22/21 |
| Display reset pin | none | GPIO4 (for 7-pin modules) |
| Watchdog timer | virtual timer `-1` | hardware timer 0 |
| CPU clock | raised to 160 MHz | stays at 160 MHz |
| Bluetooth | none | `ble.py` |
| `ssd1306` driver | built into the firmware | installed from micropython-lib by `deploy.sh` |

Pins come from `DEFAULT_PINS` in `app.py` and can be overridden per board in
`config.json` (`pins.esp32`, `pins.esp8266`). The old `"esp"` key is ignored.

## RAM budget

The ESP8266 port gives MicroPython about **36 KB** of heap. Modules loaded from
`.py` or `.mpy` files keep their bytecode in that heap, so code size is RAM.

| Item | RAM |
|---|---|
| `sensors` | ~3.5 KB |
| `net` (incl. `umqtt.simple`) | ~4.2 KB |
| `ui` | ~6.0 KB |
| `app` | ~3.8 KB |
| `gfx` + `assets` (metrics only) | ~3.6 KB |
| `ssd1306` + 2 frame buffers | ~3 KB |
| `commands` (only while answering a request) | ~1.7 KB |
| **free while running** | **~8.6 KB** (`/status` → `lowest_free_ram`) |

How it fits:
- **Compiled `.mpy`, not `.py`.** Compiling the sources on the board needs
  more RAM than is free (the first version failed with `MemoryError`).
- **`mpy-cross -O3`** leaves out line-number tables: ~6 % smaller. The price:
  tracebacks show no line numbers.
- **Compact code where it counts.** One `AirSensor` class instead of three, the
  defaults only exist inside `load_config()`, the watchdog is a timer callback,
  not a class. Every function and class costs RAM.
- **Five pages, not six.** The network page was dropped: the header already
  shows Wi-Fi/MQTT, and `/status` gives IP and signal.
- **`gc.collect()` before loading a module** for a request: the import needs a
  few KB in one piece.
- **Bitmaps in flash.** `assets.bin` stays in flash; `gfx.py` reads one glyph
  (≤ 69 bytes) into a reused buffer when drawing it. As Python data, the fonts
  took 10 KB.
- **On-demand modules.** `commands.py` and `home_assistant.py` are imported
  when needed and removed from `sys.modules` afterwards, so the garbage
  collector frees them.
- **Compact history.** 4 charts × 60 points in `array('h')`: 480 bytes instead
  of ~2 KB of list entries.

If new features run out of RAM, the next step is to **freeze** the modules into
a custom MicroPython build, which moves all code to flash (see MicroPython's
`ports/esp8266/README.md`; it needs the ESP8266 toolchain, e.g. via Docker).
On the **ESP32** none of this is tight: about 165 KB are free, and the same
code runs with Bluetooth on top. The measures above still help the ESP8266, so
they stay.
